## 1. Supabase 프로젝트 연결

### 프로젝트 정보
- **Project URL**: `https://exvcaeidzxlwxfznalsr.supabase.co`
- **anon key**: `.env.local`에 `VITE_SUPABASE_ANON_KEY`로 저장 (gitignore 처리)
- **패키지 설치**: `@supabase/supabase-js`

### 파일 생성: `src/lib/supabase.js`
```js
import { createClient } from '@supabase/supabase-js'

export const supabase = createClient(
  import.meta.env.VITE_SUPABASE_URL,
  import.meta.env.VITE_SUPABASE_ANON_KEY,
  {
    auth: {
      flowType: 'pkce',       // OAuth 코드 교환 방식 (GitHub Pages 환경 호환)
      detectSessionInUrl: true,
      persistSession: true,
      autoRefreshToken: true,
    },
  }
)

export function redirectURL() {
  return window.location.origin + import.meta.env.BASE_URL
}
```

**핵심**: `flowType: 'pkce'` 설정이 없으면 카카오 OAuth 리다이렉트 후 세션이 복원되지 않음.  
`redirectURL()` 함수는 `BASE_URL`(`/rest04/`)을 자동 포함해 개발/배포 환경 모두 호환.

## 2. DB 스키마 설계 및 적용

### 배경
수업에서 강사님이 Supabase 프로젝트를 학생들과 공유하는 방식으로 진행.  
하나의 Supabase 프로젝트에 여러 앱이 공존하므로 **`r04_` 접두어로 테이블 격리**.

### 적용 방법
강사님 GitHub `aebonlee/rest04/supabase/schema.sql` 내용을  
Supabase 대시보드 → SQL Editor → New 탭에 붙여넣기 후 Run 실행.

### 생성된 테이블

#### `r04_profiles`
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | uuid (PK) | auth.users.id 참조 |
| nickname | text | 표시 이름 (기본값: '회원') |
| role | text | 'user' 또는 'admin' (기본값: 'user') |
| created_at | timestamptz | 생성 시각 |

#### `r04_posts`
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | uuid (PK) | 자동 생성 |
| category | text | 'notice' / 'free' / 'qna' |
| title | text | 제목 |
| content | text | 본문 |
| author_id | uuid | auth.users 참조 |
| author_name | text | 작성자 표시 이름 |
| view_count | int | 조회수 (기본값: 0) |
| comment_count | int | 댓글 수 (기본값: 0, 트리거로 자동 갱신) |
| created_at | timestamptz | 작성 시각 |
| updated_at | timestamptz | 수정 시각 |

#### `r04_comments`
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | uuid (PK) | 자동 생성 |
| post_id | uuid | r04_posts 참조 (CASCADE) |
| content | text | 댓글 내용 |
| author_id | uuid | auth.users 참조 |
| author_name | text | 작성자 표시 이름 |
| is_answer | boolean | 운영자 답변 여부 (기본값: false) |
| created_at | timestamptz | 작성 시각 |

### DB 함수

#### `r04_is_admin()`
현재 로그인 유저가 admin인지 판별하는 헬퍼 함수.  
`security definer`로 선언해 RLS 재귀 호출 방지.

#### `r04_sync_comment_count()`
댓글 INSERT/DELETE 시 `r04_posts.comment_count` 자동 갱신 트리거 함수.  
`security definer` 필수 — 남의 글에 댓글 달 때 RLS를 우회해 카운트 갱신 가능.

#### `r04_increment_view(post_id uuid)`
조회수 +1 함수. `security definer`로 비로그인 사용자도 조회수 증가 가능.

### RLS(Row Level Security) 정책
| 테이블 | 정책 | 조건 |
|--------|------|------|
| r04_profiles | SELECT | 누구나 |
| r04_profiles | INSERT | 본인 id + role='user' 고정 (role 상승 차단) |
| r04_posts | SELECT | 누구나 |
| r04_posts | INSERT | 로그인 유저 + 공지사항은 admin만 |
| r04_posts | UPDATE/DELETE | 작성자 본인 또는 admin |
| r04_comments | SELECT | 누구나 |
| r04_comments | INSERT | 로그인 유저 + is_answer=true는 admin만 |
| r04_comments | DELETE | 작성자 본인 또는 admin |

## 3. 인증 구현

### `src/context/AuthContext.jsx` 전면 재작성

**이전 방식 (문제점)**:
- `user.email === 'seowoo92@gmail.com'`으로 admin 하드코딩
- profile 시스템 없음
- 카카오 로그인 시 email이 NULL이면 admin 판별 불가

**새로운 방식**:
- `r04_profiles.role === 'admin'`으로 DB 기반 admin 판별
- 최초 로그인 시 `r04_profiles`에 프로필 자동 생성 (트리거 없이 클라이언트에서 처리)
- 닉네임 도출 우선순위: `user_metadata.nickname` → `name` → `full_name` → `preferred_username` → 이메일 앞부분 → '회원'

**제공하는 context 값**:
```js
{
  session,       // Supabase 세션 객체
  user,          // auth.users 유저 객체
  profile,       // r04_profiles 행 { id, nickname, role }
  isAdmin,       // profile.role === 'admin'
  isLoggedIn,    // !!session
  loading,       // 초기 세션 로드 중 여부
  signIn,        // 이메일/비밀번호 로그인
  signUp,        // 이메일/비밀번호 회원가입 (닉네임 파라미터 지원)
  signInWithKakao, // 카카오 OAuth
  signOut,
  reloadProfile, // 프로필 강제 재로드
}
```

## 4. 카카오 OAuth 연동

### Kakao Developer Console 설정

1. **앱 생성**: [developers.kakao.com](https://developers.kakao.com) → 내 애플리케이션 → 앱 추가
2. **REST API 키** 발급 후 Supabase Auth 공급자에 등록
3. **플랫폼 등록**: 앱 설정 → 플랫폼 → Web → `https://seowoo92.github.io` 등록
4. **카카오 로그인 활성화**: 제품 설정 → 카카오 로그인 → 활성화 ON
5. **Redirect URI 등록**: `https://exvcaeidzxlwxfznalsr.supabase.co/auth/v1/callback`
6. **비즈앱 전환**: 개발자 테스트용 비즈 등록으로 전환 (이메일 동의항목 잠금 해제)
7. **동의항목**: 카카오계정(이메일) → 선택동의로 변경

### Supabase Auth 설정
- Authentication → Providers → Kakao → Enable
- REST API Key / Client Secret 입력
- Site URL: `https://seowoo92.github.io/rest04` (오타 주의: `.com.io` 아닌 `.io`)
- Redirect URLs: `https://seowoo92.github.io/rest04/` 추가

### 트러블슈팅

| 에러 | 원인 | 해결 |
|------|------|------|
| KOE004 | 웹 플랫폼 도메인 미등록 | Kakao 앱 대표 도메인에 `https://seowoo92.github.io` 등록 |
| KOE205 | Redirect URI 미등록 | Supabase callback URL을 Kakao Redirect URI에 등록 |
| KOE205 (지속) | `account_email` 동의항목 권한 없음 | 비즈앱 전환 → 이메일 선택동의 허용 |
| 카카오 이메일 NULL | 카카오 계정에 이메일 미연동 | ID 기반으로 admin 설정 방식으로 대응 |

### 권한 구조
- **공지사항 작성/수정/삭제**: admin만 (RLS + 클라이언트 guard 이중 처리)
- **자유게시판 작성**: 로그인 유저 누구나
- **자유게시판 수정/삭제**: 작성자 본인 또는 admin
- **목록/상세 읽기**: 비로그인 포함 누구나

### `r04_posts` 단일 테이블 방식
이전에는 `notices`, `posts` 테이블을 분리 → `r04_posts` 하나에 `category` 필드로 통합.  
- 공지사항 조회: `.eq('category', 'notice')`
- 자유게시판 조회: `.eq('category', 'free')`

### 글쓰기 author_name 처리
`BoardWrite.jsx`에서 직접 이름 입력 받던 방식 → `profile.nickname` 자동 적용으로 변경.

## 트러블슈팅 종합

| 문제 | 원인 | 해결 |
|------|------|------|
| 카카오 로그인 후 세션 복원 안 됨 | PKCE flow 미설정 | `supabase.js`에 `flowType: 'pkce'` 추가 |
| admin 설정 UPDATE No rows returned | 카카오 이메일 NULL이라 email로 조회 불가 | `auth.users`에서 id 직접 조회 후 id로 UPDATE |
| 공지 작성 권한 오류 | 이전 코드가 email 기반 isAdmin 사용 | `profile.role === 'admin'` 방식으로 전환 |
| 프로필 미생성 | 코드 배포 전 로그인한 경우 | 로그아웃 후 재로그인 시 자동 생성 |
| Supabase Site URL 오류 | `.github.com.io` 오타 | `.github.io`로 수정 |

## 배운 것
- Supabase RLS는 DB 레벨 보안, 클라이언트 guard는 UX 목적 — 반드시 둘 다 필요
- `security definer` 함수: 호출자 권한이 아닌 함수 정의자 권한으로 실행 → RLS 우회 가능
- OAuth PKCE 플로우: Authorization Code를 클라이언트가 code_verifier로 교환 → GitHub Pages같은 정적 배포 환경에서 안전
- 공유 Supabase 프로젝트에서 테이블 접두어(`r04_`)로 격리하는 패턴
- 카카오 비즈앱 전환 없이는 이메일 동의항목 사용 불가 (KOE205 에러)
